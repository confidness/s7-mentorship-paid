# Languages

Kazakh, Russian and English, switchable from the header at any moment — nothing reloads and
nothing is lost. Over a thousand interface strings, each written three times.

## How it works

`t(key, vars)` in `src/i18n/index.tsx` looks the key up in `UI` (`src/i18n/ui.ts`), where every
entry is `{ en, ru, kk }`. An unknown key falls back to English, then to the key itself, so a
gap is visible instead of blank. `{name}`-style placeholders are filled from `vars`.

The active locale is a module variable, so `t()` can be called from anywhere — plain functions,
helpers, deeply nested components — without threading a hook through every file. The provider
owns the state and re-renders the tree when it changes. The choice is stored per browser under
`s7-locale`; with none stored, the browser's language decides (`kk` is Kazakh, `ru`, `uk` and
`be` are Russian, anything else is English).

Keys are slugs of the original English text, so a missing translation is obvious in review.

## Dates and numbers

Dates and numbers follow the interface language rather than the operating system. Chrome
resolves `kk-KZ` but ships no Kazakh month or weekday names, so those are assembled in
`i18n/index.tsx` instead of being handed to `Intl`. Kazakh numbers are grouped as Russian ones
are.

## Stored text is a key, not a sentence

Text the app generates and stores — notifications, XP history, a new student's goal — is kept
as a dictionary key plus the ids it refers to (`TextVars` in `src/lib/types.ts`), never as a
finished sentence. A notification written in Kazakh therefore reads in Russian the moment the
language changes, instead of being frozen in whatever language was active when it was written.
`t()` falls back to the key itself, so text a person typed still renders as typed.

The same holds on the server. The `notifications` table stores `title`, `body` and `vars`, and
the reader's language is not known when the row is written and may change afterwards.

## Adding a string

1. Add the entry to `src/i18n/ui.ts` with all three languages. A string present in `en` and
   missing in `ru` or `kk` is a defect, not a work in progress.
2. Use it through `t('the_key')`. A literal user-facing string in a component is a finding.
3. If the string takes values, write them as `{name}` and pass `vars`.

Do not remove a key because nothing references it literally. Some are built at runtime:
`plural()` builds `course_one` and `course_many` from a stem, navigation labels arrive through
`t(item.label)`, and the code checker looks its rules up by id. A sweep for unreferenced keys
will take these with it, and the failure is a key printed in place of a sentence.

## Course content

`src/i18n/content.ts` merges a translation pack over the English canonical for built-in
curriculum text: courses, modules, lessons, achievements and levels. English lives in
`lib/curriculum.ts` and stays the source of truth — ids, order, code samples and check rules
never move; a pack only replaces the words a learner reads. The curriculum is empty (see
[the decision](decisions/0002-curriculum-retired.md)), so the packs are nearly so too, and the
machinery stays because a revived track would need it.

Lessons mentors write are not translated. They are in whatever language the mentor wrote them.

## The AI mentor

The local knowledge base is written in English with Russian and Kazakh twins in
`src/i18n/ai.ru.ts` and `ai.kk.ts`, keyed by the same entry ids. The server prompt asks the
model to answer in the interface language. See [the AI mentor](ai-mentor.md).
